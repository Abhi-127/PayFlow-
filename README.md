# PayFlow - Build the backend of a UPI-style payment app

## Project Overview

PayFlow is a simplified digital payment backend application developed using Spring Boot. The application provides REST APIs for user registration, user lookup, user listing, and money transfer recording. The project follows a layered architecture consisting of Controller, Service, Repository, and Entity layers.

# Demonstration of @RequestBody

With `@RequestBody`, Spring converts incoming JSON data into a Java object automatically.

Without `@RequestBody`, Spring does not read the JSON request body, resulting in all object fields being null.

# Custom Query Approaches

### Derived Query Method

```java
findByUpiId(String upiId)
```

Spring generates the query automatically from the method name.

### JPQL Query

```java
@Query("SELECT u FROM User u WHERE u.balance > :amount")
```

JPQL is database-independent and works on entity objects.

### Native SQL Query

```java
@Query(value="SELECT * FROM users", nativeQuery=true)
```

Native SQL is database-specific and less portable, making it the least preferred option.

# Conceptual Questions

## 1. Request Lifecycle

When a client sends a request, it first reaches the embedded Tomcat server. The request is then handled by the DispatcherServlet, which uses HandlerMapping and HandlerAdapter to locate and invoke the appropriate controller method. The response is converted to JSON and returned to the client.

## 2. Serialization

Jackson ObjectMapper converts JSON data into Java objects and vice versa. If a JSON field name does not match the Java field name, the value may not be mapped correctly and can remain null.

## 3. Spring Boot Features

* Embedded Server: Runs the application using embedded Tomcat.
* Auto Configuration: Configures Spring MVC, JPA, and H2 automatically.
* Production Ready Defaults: Provides logging, monitoring, and sensible defaults.

## 4. Spring vs Spring Boot

Using Spring would require manual configuration of Tomcat, DispatcherServlet, Hibernate, and database connections. Spring Boot automates these configurations and reduces boilerplate code.

## 5. Stateless REST

A stateless API does not store information about previous requests. Each request contains all the data needed for processing. This makes the application scalable and suitable for load-balanced environments.

## 6. Persistence

If transaction data were stored in a Java List, all records would be lost when the application restarts. Databases provide permanent storage and ensure transaction records remain available even after server restarts.
